Scan your project in 10 seconds.

DepSentinel checks your dependencies before they are installed or deployed and blocks malicious packages, typosquatting, dangerous install scripts and vulnerabilities. Free, local and open source.

go install github.com/AlejandroMolines/depsentinel/cmd/depsentinel@latest

With Go 1.22 or later you install the depsentinel command. Then, inside your project: depsentinel scan. (You can also use Docker without installing: see README and installation docs.)

What it looks for in every scan

Seven checks, each with an explanation and a concrete way to fix it.

Known malicious packages
Every dependency is checked against OSV (the OpenSSF MAL-* advisories) and a signed local database that keeps working offline. It recognizes cases such as event-stream@3.3.6, crossenv or the hijacked versions of ua-parser-js.
Typosquatting
Names almost identical to popular ones: reactt, lodassh, reqeusts. It measures edit distance and package age so legitimate packages are not flagged.
Dangerous install scripts
Reads preinstall, install and postinstall. With --deep it downloads the package, checks its hash against the lockfile and reads the code those scripts run: remote downloads, reverse shells, credential theft.
Known vulnerabilities
CVE and GHSA advisories via OSV, with CVSS severity and the version that fixes them. depsentinel fix bumps direct dependencies and pins GitHub Actions to a SHA.
Abandoned dependencies
Packages with no releases for years, deprecated or yanked versions, and packages that no longer exist in the registry.
Odd version or maintainer changes
99.x versions typical of dependency confusion, new publishers or maintainers right on the latest version, and tarballs that do not match the lockfile.
Beyond npm
PyPI, Go, Dockerfiles and GitHub Actions: curl | sh in a Dockerfile, actions not pinned to a SHA, pull_request_target checking out the PR, command injection in workflows.

From zero to blocking in CI

Three steps. The first two need no account and no server.

  1. Install it

    go install github.com/AlejandroMolines/depsentinel/cmd/depsentinel@latest

    A single binary with no dependencies. There is also a Docker image, and binaries with checksums on every release.

  2. Scan your project

    cd my-project
depsentinel scan

    It picks up whatever lockfiles, Dockerfiles and workflows it finds. depsentinel report --html --open opens the dashboard with the details of every package.

  3. Make CI enforce it

    - uses: AlejandroMolines/depsentinel/action@v1
  with:
    fail-on: high

    It comments the result on every pull request and fails the build on high risk. An exception only counts if it carries a written justification.

What leaves your machine, and what does not

DepSentinel runs on your computer or in your CI. There is no account, no server of ours and no telemetry.

Leaves, only when online

  • The name and version of each public package, to api.osv.dev, to look up security advisories.
  • The package name, to registry.npmjs.org, pypi.org or proxy.golang.org, to read dates and maintainers.

Never leaves

  • Your code, your full lockfile, your machine's paths, tokens and environment variables.
  • Packages installed from git, local paths or URLs.

You decide

--offline opens no connection at all and uses only the local rules. --no-osv and --no-registry switch each source off separately, and DEPSENTINEL_OSV_URL points to an internal mirror. The malicious-package database is downloaded with depsentinel db update and verified with an Ed25519 signature before use. Only two commands that you run on purpose reach other places: db update downloads the feed from the repository and fix queries api.github.com to resolve the SHA of an action.
